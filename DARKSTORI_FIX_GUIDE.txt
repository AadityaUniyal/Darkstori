SECTION 1 — WHAT THE APP IS SUPPOSED TO DO
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Darkstori is a quick-commerce intelligence platform for India (5 cities:
Bangalore, Delhi, Mumbai, Hyderabad, Pune). It lets operators of dark stores
(micro-warehouses powering 10-minute delivery) see:

  • Dashboard      → KPIs, coverage scores, store counts per city
  • Neighborhoods  → neighborhood-level demand DNA (demographics, competition)
  • Simulator      → "what if I open a store here?" ROI simulation
  • Analytics      → heatmaps, platform comparison (Blinkit/Zepto/Instamart)
  • Forecast       → 90-day AI demand predictions per pincode
  • Resilience     → perishables zero-waste cockpit (product batch tracking)
  • Algorithm Lab  → ML model comparison & explainability

Auth flow: register/login → JWT → all pages behind PrivateRoute.

will fail CORS checks.

is added, or use socketio's cors_allowed_origins parameter:

  # Mount AFTER CORSMiddleware is added
  app.mount("/socket.io", socketio.ASGIApp(sio))

IMPACT: Settings has DATABASE_URL: str = "" as the default. If .env

BUG #7 — Redis/Cache removed but CELERY_BROKER_URL still in docker-compose
──────────────────────────────────────────────────────────────────────────
IMPACT: requirements/base.txt explicitly notes "Redis removed" and cache
is replaced with NoOpCache. But docker-compose.yml still spins up a Redis
container and injects REDIS_URL/CELERY_BROKER_URL. This wastes resources
and misleads developers.

FIX (Option A — keep Redis for real caching): Re-add redis==5.2.0 to
requirements and replace NoOpCache with a real Redis cache implementation
using aioredis.

FIX (Option B — fully remove Redis): Remove the redis service from
docker-compose.yml and remove Redis env vars. Leave NoOpCache as-is.

Recommendation: Keep Redis (Option A). The app has 60 req/min rate
limiting done in-memory per process — under a multi-worker deployment
this breaks (each worker has its own counter). Redis-backed rate limiting
is the proper fix.

BUG #9 — Frontend VITE_API_URL mismatch in Docker
───────────────────────────────────────────────────
IMPACT: In docker-compose.yml, the frontend service sets
VITE_API_URL=http://localhost:8000. But Vite env vars are baked in at
BUILD TIME, not runtime. Since the frontend is built inside the Docker
image, VITE_API_URL is undefined at build time (it's only passed as a
runtime env var) and the frontend defaults to http://localhost:8000
(correct for local dev), but this URL is inaccessible from the browser
if the app is deployed remotely.

FIX: In frontend/Dockerfile, pass the API URL as a build argument:
  ARG VITE_API_URL=http://localhost:8000
  ENV VITE_API_URL=$VITE_API_URL
  RUN npm run build

  Then in docker-compose.yml:
    frontend:
      build:
        args:
          VITE_API_URL: ${API_URL:-http://localhost:8000}

PHASE 3 — Production deployment (Render / Railway / VPS)
──────────────────────────────────────────────────────────

RECOMMENDED FREE/CHEAP STACK:
  • Backend  → Render.com (free tier for FastAPI, or $7/mo starter)
  • Database → Neon.tech (free PostgreSQL, already referenced in codebase)
  • Frontend → Vercel (free, already referenced in ALLOWED_ORIGINS)
  • MLflow   → Disable (set MLFLOW_ENABLE_TRACKING=false for initial deploy)

BACKEND ON RENDER:
  1. Connect GitHub repo to Render
  2. New Web Service → Root Directory: . → Runtime: Python 3.12
  3. Build Command:  pip install -r backend/requirements/base.txt -r backend/requirements/ml.txt
  4. Start Command:  uvicorn backend.app:app --host 0.0.0.0 --port $PORT
  5. Set environment variables:
       DATABASE_URL=<your Neon connection string>
       JWT_SECRET_KEY=<strong random key>
       ENCRYPTION_KEY=<fernet key>
       ENVIRONMENT=production
       DEBUG=False
       ALLOWED_ORIGINS=https://your-app.vercel.app
  6. Add health check: /health

FRONTEND ON VERCEL:
  1. Import GitHub repo to Vercel
  2. Root Directory: frontend
  3. Build Command: npm run build
  4. Output Directory: dist
  5. Environment Variables:
       VITE_API_URL=https://your-backend.onrender.com
  6. Deploy

DATABASE SETUP (NEON):
  1. Create project at neon.tech
  2. Copy connection string (postgresql://user:pass@host/db?sslmode=require)
  3. Set as DATABASE_URL in Render
  4. Run migrations:
     In Render Shell: alembic upgrade head
     Or use init_db() approach (auto-runs on first start)

DOCKER COMPOSE (self-hosted VPS):
  1. Create .env.prod from .env.example
  2. docker compose -f docker-compose.prod.yml up -d
  3. Ensure ports 80 (frontend) and 8000 (API) are open in firewall

SECTION 6 — IMPROVEMENTS TO MAKE THE APP PRODUCTION-GRADE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

IMPROVEMENT A — Proper seed data with realistic Indian city data
────────────────────────────────────────────────────────────────
The current seed_data.py seeds synthetic data but the exact content is
unknown. For a compelling demo, seed_data should include:
  - ~50-100 realistic dark store locations per city
  - ~200 neighborhood records with plausible DNA scores
  - ~1000 synthetic orders over 90 days for trend charts
  - 5-10 competitor stores per city per platform

IMPROVEMENT B — Replace MLflow with simpler model persistence
──────────────────────────────────────────────────────────────
MLflow is enterprise-grade and overkill for a demo/MVP. It adds a whole
additional service. For v1, replace with joblib + file-based model storage:
  - Train models, serialize to models/demand_model.pkl
  - Load with joblib.load() on startup
  - Remove the entire mlflow service from docker-compose.yml
  This makes deployment dramatically simpler.

IMPROVEMENT C — Add an /api/demo/seed-and-login endpoint
─────────────────────────────────────────────────────────
For demo purposes, a single endpoint that:
  1. Seeds fresh demo data
  2. Creates/resets a demo@darkstori.in account
  3. Returns a JWT token
Makes it trivial for anyone to try the app without manual setup.

IMPROVEMENT D — Error states in the React frontend
───────────────────────────────────────────────────
Currently, if the backend is unreachable, pages silently show empty
state. Add a global API error toast:
  - In api.js axios response interceptor: check for network errors
  - Emit a "api:error" event
  - Show a banner: "Backend unreachable — check your connection"

IMPROVEMENT E — nginx SPA fallback (Critical for React Router)
───────────────────────────────────────────────────────────────
Verify that frontend/nginx/default.conf has:
  location / {
    root /usr/share/nginx/html;
    index index.html;
    try_files $uri $uri/ /index.html;  ← THIS LINE IS ESSENTIAL
  }
Without it, direct URLs like /dashboard return 404 after deployment.

IMPROVEMENT F — GitHub Actions CI/CD pipeline
──────────────────────────────────────────────
The only workflow in .github/workflows/ is an auto-merge Dependabot helper.
There is no actual CI (test + lint) or CD (deploy) pipeline.

Add .github/workflows/ci.yml:
  on: push
  jobs:
    test-backend:
      - pip install -r backend/requirements/dev.txt
      - pytest backend/tests/ -v
    test-frontend:
      - npm install && npm run lint && npm run test

Add .github/workflows/deploy.yml:
  on: push to main
  jobs:
    deploy:
      - Trigger Render/Vercel deploy via webhook
