## 🎯 The Problem & Value Proposition

In high-density quick-commerce (Blinkit, Zepto, Instamart, Gopuff), dark store networks operate at blistering speeds (under 10 minutes from picker scan to rider dispatch). However, inventory decision-making suffers from severe systemic vulnerabilities:

1. **The Expiry Cliff:** Fresh produce, dairy, bakery, and meat items write off 4% to 8% of GMV annually because traditional WMS rules rely on rigid FIFO (First-In, First-Out) or static 24-hour markdowns.
2. **Floor Count Discrepancies (Shrinkage Blindspots):** In fast-paced micro-warehouses, phantom inventory and misplacements skew algorithmic discount recommendations when models assume POS system inventory matches reality.
3. **Decoupled Execution:** Markdowns generated by central analytics teams take hours to reach live store catalog feeds, during which product shelf-life expires.

### **The Darkstori Solution**
Darkstori connects **real-time order telemetry**, **WMS freshness batch data**, and **double-entry stock ledgers** to a **Sigmoid Markdown Recommendation Engine** with a **Human-in-the-Loop Decision Queue**. Store leads reconcile physical floor shrinkage with one click, triggering automated HMAC-signed catalog price updates instantly.

## 📐 Algorithmic Formulation & Counterfactual Proof

### **1. Dynamic Sigmoid Markdown Formulation**
Rather than cutting prices linearly or abruptly at the last minute, Darkstori models the markdown trajectory as a continuous sigmoid function bounded by the product's gross margin floor:

$$\text{Discount}(t) = D_{\max} \cdot \left(1 - \frac{1}{1 + e^{-k \cdot (t_{\text{crit}} - t_{\text{rem}})}}\right) \cdot \Phi(\text{velocity})$$

Where:
* $t_{\text{rem}}$ is the remaining shelf life in hours until expiration.
* $t_{\text{crit}}$ is the inflection threshold where urgency transitions into aggressive clearance.
* $k$ is the decay steepness parameterized by historical dark store sell-through velocity.
* $D_{\max} = 1 - \frac{\text{Cost Price}}{\text{MRP}}$ ensures markdowns never violate the break-even margin floor.
* $\Phi(\text{velocity}) = \max\left(0, 1 - \frac{v_{\text{observed}}}{v_{\text{target}}}\right)$ suppresses markdowns if organic store velocity will clear stock naturally.

## 🏢 Enterprise Multi-Tenancy & Security Boundary

Darkstori enforces tenant boundary isolation across every layer of the technology stack:

- **Row-Level Organization Ownership:** Every critical domain entity (`DarkStore`, `StockLedger`, `AuditLog`, `StoreSimulation`, `Playbook`, `ExpansionDecision`) carries a strict `organization_id` foreign key.
- **Token-Bound Authorization:** The `verify_token` dependency extracts the authenticated tenant context from signed JWT claims. Direct tenant ID injection via query parameters or body payloads is rejected.
- **Negative Cross-Tenant Protection:** Fully verified by [`test_tenant_isolation.py`](backend/tests/test_tenant_isolation.py)—Org A cannot read, query, update, or resolve batches, playbooks, or simulations owned by Org B (returning `404 Not Found` or `403 Forbidden`).
- **Audit Logging:** Every critical decision, floor override, and batch mutation appends an immutable entry to `audit_logs` with the operator's user ID, IP address, and cryptographic timestamp.

## 🚀 Local Development Quickstart

### Prerequisites
- **Python:** 3.11+
- **Node.js:** 20+
- **PostgreSQL / Neon:** Recommended (or SQLite for local zero-dependency testing)

### Step 1: Clone & Configure Environment
```bash
git clone https://github.com/AadityaUniyal/Darkstori.git
cd Darkstori

# Copy environment template
cp .env.example .env
```

Generate secure cryptographic keys and update your `.env`:
```bash
# Generate JWT Secret
python -c "import secrets; print(secrets.token_urlsafe(48))"

# Generate Fernet Encryption Key
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

### Step 2: Database Migration
```bash
python -m pip install -r requirements.txt
python -m alembic -c alembic.ini upgrade head
```

### Step 3: Run the Application
In your first terminal (Backend API):
```bash
uvicorn backend.app:app --host 127.0.0.1 --port 8000 --reload
```

In your second terminal (Frontend Client):
```bash
cd frontend
npm ci
npm run dev
```
Open [http://localhost:5173](http://localhost:5173) in your browser.

## 🚢 Cloud Deployment & Vercel Configuration

Darkstori is pre-configured for zero-friction serverless deployment on **Vercel**:

* **Root Configuration (`vercel.json`):**
  * Automatically builds the React frontend: `cd frontend && npm ci && npm run build`
  * Deploys the FastAPI serverless ASGI function via `api/index.py`
  * Routes `/api/(.*)` to the Python ASGI handler and `/(.*)` to Vite static assets.

* **Required Environment Variables in Vercel:**
  ```ini
  DATABASE_URL=postgresql://user:pass@ep-hostname.neon.tech/neondb?sslmode=require
  JWT_SECRET_KEY=your_cryptographically_secure_jwt_secret
  ENCRYPTION_KEY=your_cryptographically_secure_fernet_key
  ALLOWED_ORIGINS=https://darkstori.vercel.app,http://localhost:5173
  ENVIRONMENT=production
  ```
